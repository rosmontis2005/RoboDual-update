  这样 hidden-state blend 只是其中一种接入方式，而不是唯一方案。你现在的负结果并不说明“这个问题不重要”，反而说明“直接线性混 hidden state 很可能不是正确做法”。

  当前实现里，slow refresh 后会立刻替换 self.action 和 self.hidden_states，再用 handover 去混新旧 ref action 和 hidden state，见 RoboDual/vla-scripts/
  dual_sys_evaluation_0424test.py:223 和 RoboDual/vla-scripts/dual_sys_evaluation_0424test.py:332。6 月那次实验的问题也很明确：success 掉到 78.7%，handover active 占 24.8%，active 时
  dp_ref_l2_ee6 约升了 6 倍，记录在 RoboDual/personal_log/exp_log/log0609.md:15。

  可能失败原因

  1. hidden state 不是动作空间，不一定能线性插值。
     action 可以理解成物理量，线性混合还有控制意义；hidden state 是 generalist 对当前图像、语言、动作 token 的内部表示。0.25 new + 0.75 old 不一定落在 specialist 训练见过的表示流形上。

  2. 当前同时混了 ref action 和 hidden state，无法定位问题。
     --slow_handover_steps 4 --slow_handover_blend_hidden 实际是“ref-action ramp + hidden ramp”的组合，不是纯 hidden ablation。负结果可能来自 hidden，也可能来自 ref 被缩放，也可能来自
     二者不一致。

  3. 旧 ref 已过期时，当前 blend 会把新 ref 缩小。
     在 age>=8 后旧 ref 已经为空。此时 refresh 后 alpha=0.25，相当于把新 ref action 变成 25% 强度，而不是从旧 ref 平滑过渡。这会制造一种 specialist 没见过的条件：弱 ref action + 混合
     hidden state。

  4. gripper 维度被连续混合也可能 OOD。
     gripper 通常接近离散开/合，ref action 里混出 0.25、0.5 这种中间值，可能比空指导还糟。

  5. risk refresh 发生在本来就不稳定的状态。
     risk trigger 不是随机发生，而是集中在 aggregation / jerk / sample variance 高的位置。你把最激进的 hidden/ref 混合放在最不稳定的时刻，失败概率会被放大。

  6. 只混 guidance，没有处理 temporal aggregation buffer。
     最终动作还经过 action buffer 的 temporal ensemble。slow guidance 换了，但 buffer 里还留着旧条件下的预测，新旧轨迹仍会拉扯。

  我建议下一步这样做

  第二步我会优先改两个实现细节：

  1. 旧 ref 已过期时，不要 blend old zero ref。
     如果 old ref 已经过期，直接使用完整 new ref，只在最终动作层面限幅。也就是：有旧有效 chunk 才 action-space blend；旧 chunk 空了就不要把新 chunk 缩成 25%。

  2. hidden 不做线性 blend，改成 delayed commit 或 gated commit。
     更合理的是：
      - slow 可以先算出新 hidden；
      - 暂存为 pending hidden；
      - 只有当新条件下的 action 与当前轨迹差异小于阈值时才 commit；
      - 否则继续用旧 hidden / empty ref，等 max age 或稳定窗口再切。

  这比线性 hidden blend 更符合你的目标：不是“把两个 hidden 平均”，而是“避免新 hidden 突然破坏当前控制轨迹”。

  更有科研味的版本
  最终可以把这条线写成三层：

  1. Detection: risk/profile 指标发现当前 chunk transition 风险。
  2. Safe Commit: 新 slow guidance 不立即硬切，而是经过 action consistency gate。
  3. Continuation: 如果 gate 不通过，用 action-level limiter 或 learned continuation 平滑过渡。

  这样导师关心的“动态 slow call 导致 chunk 突变”就被正面处理了，而且当前 hidden blend 的负结果也能变成一个合理实验结论：naive latent interpolation 会造成 OOD conditioning，因此需要
  gated / action-aware handover。
